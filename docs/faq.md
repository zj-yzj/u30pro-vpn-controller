# 常见问题

[中文](faq.md) · [English](faq.en.md) · [主页](../README.md) · [使用说明](usage.md)

以下回答针对当前源码：原生应用 1.2.0 / version code 6，已知开发集成为 U30 Pro、MU5358/B23、原厂 Android/root。图像均为示意或 mock 预览，不能当作一次新设备验收。

## 1. 下载源码、构建 APK 或导入插件后就能使用吗？

真实设备还需要完成集成。仓库没有刷机包、root 工具、通用安装器、代理核心、真实订阅、签名身份或原设备信任记录。未签名 APK 不能正常安装；导入网页插件只增加界面。

维护者须准备 root 私有 `/data/adb/u30pro-vpn`、Mihomo、provider、网关基线、Go helper、管理密钥、APK 信任与启动恢复。`gateway/reference/` 是固定布局参考，启动模板没有完整安装事务恢复阶段。不要直接复制到未知设备执行。见[集成边界](device-integration.md)、[网关参考](../gateway/reference/README.md)。

只想查看界面可按[离线预览](usage.md#在电脑上预览)运行，无需真实设备或订阅。

## 2. 能用于其他 U30 Pro 固件、其他随身 Wi-Fi 或 OpenWrt 吗？

目前只明确已知开发环境，不能据此宣称适配所有固件或硬件。Android 的 `minSdk 26` 是构建约束，不是全部 Android 8.0+ 设备可用的承诺。原厂首页识别、圆屏、安全区、root 命令、SFP、接口和路由布局均有系统假设。

参考网关固定使用 `br0`、`192.168.0.0/24`、`U30VPN`、特定路由表/规则和 `/proc/net/sfp/enable`。移植需要重新审查网络对象归属、DNS、关闭恢复、启动和断电恢复，见[兼容矩阵](../README.md#兼容范围与前置条件)。

## 3. “本机服务未连接”“本机授权未通过”或按钮不可用怎么办？

先区分连接与信任：前者可能是 `webbridge` 未运行、后端未初始化或本机入口不匹配；后者需要维护者核实当前包名、UID、APK 安装路径和 SHA-256 信任记录，以及目录所有权/权限。重建 APK 会改变摘要；更换签名还影响 Android 同包更新。

等本机状态读取成功后重试；处理中或状态不新鲜时，控件会暂时禁用。不要通过开放 TCP 管理端口、删除 UID/APK 校验或放宽私有目录权限解决。安装同一个 APK 也不能使任意 rooted 设备自动具备所需后端。

## 4. 退出应用、关闭网页或关闭悬浮入口会关闭 VPN 吗？

不会。这些操作仅影响控制界面。若要停止 VPN，回主页显式点“关闭 VPN”，等实际状态确认后检查原厂联网是否恢复。目标开关状态、实际运行状态和客户端真实联网是不同观察量。

开启状态和节点选择由管理器持久化，重启恢复还依赖正确的 root 启动集成；不能从“设置已保存”推断某个新固件已通过重启验收。

## 5. 左滑测速怎么用？为什么底部“刷新”与网页“刷新”不同？

圆屏节点页按住普通节点向左滑，展开独立“测速”按钮，再点击；右滑收起。没有固定长按时间门槛，已选节点也可滑动；`Auto` 无单独测速按钮。单节点测速不更改任何节点/选择组。

圆屏节点页底部“刷新”手动测试当前订阅整个列表。网页右上角“刷新”只读取已有状态；当前网页没有批量或单节点测速按钮。两种原生测速均要求 VPN 已开启且实际运行，不会自动开启 VPN。详见[节点操作](usage.md#节点选择与手动测速)。

## 6. 会后台自动测速吗？`Auto` 如何选择？“未测速”或失败说明什么？

没有周期外部节点测速。provider 无自动 `health-check`，`VPN` 与 `Auto` 为 `select`。整批手动测试完成后，可根据本轮成功结果优选内层 `Auto`；外层手动选择保留。外层本来选 `Auto` 时，内层变化会影响实际出口。

前台、网页和可选悬浮入口仍轮询本地状态，supervisor 检查进程/TUN/路由。订阅应用保留必要验证；正常 VPN、DNS 和下载仍使用网络，不能把“无自动测速”理解成“无网络访问”。

结果是固定 `https://www.gstatic.com/generate_204` 目标、预期 HTTP 204 的延迟样本（ms），不是带宽。“未测速”表示没有测量；历史失败只描述该次检查，不证明当前所有业务不可用。状态轮询不会让旧测量变成新测量。

## 7. 订阅支持哪些格式？为什么浏览器能打开，设备更新仍失败？

规范化支持 Clash/Mihomo 风格 inline `proxies` 或节点映射列表，不是任意客户端格式/远程 provider 的通用转换服务。它限制输入体积、深度和节点数，拒绝危险文件引用等；最终还由设备 Mihomo 校验节点协议和字段。

下载器要求 HTTPS、443、无 URL userinfo/fragment、受限制的公网 IPv4 连接和有效 TLS。设备 DNS、证书库、网络路径、重定向或格式也可能与电脑浏览器不同，因此浏览器可打开不等于设备可下载应用。

圆屏只更新已保存 URL；新建或更换链接在 UFI“订阅”页完成。链接可能含凭据，不要贴进公开问题。详见[订阅管理](usage.md#订阅管理)。

## 8. 订阅更新失败会丢失节点或关闭 VPN 吗？

下载/解析/验证失败保留旧配置；应用阶段有备份、事务摘要、恢复与锁检查，并尝试恢复旧配置。若选中节点在新列表消失，成功更新会回到 `Auto` 并提示。

恢复本身也可能失败。出现“恢复未完成”或“应用失败”后，应刷新并核实实际运行/出口，不要认定 VPN 一定保持或恢复。VPN 开启时更新会做一次当前出口 HTTPS 验证，这不启用周期测速。订阅操作事务也不是首次安装、升级或断电恢复的完整替代品。

## 9. 悬浮入口为什么不显示？通知和系统授权是否必需？

先在“更多 → 快捷入口”开启，并在系统设置允许显示在其他应用上层。入口按实现仅在解锁的原厂首页显示，在控制页、其他页面、锁屏和息屏隐藏；首页识别失败或本机服务不可用时也不显示。返回首页后给本地读取留出时间。

该入口使用 Android 前台服务及其通知，状态/可见性在本机轮询。权限页不可用、固件限制或首页识别变化需要维护者审查，应用无法绕过系统授权。关闭快捷入口不停止 VPN。见[悬浮说明](usage.md#首页悬浮快捷入口)。

## 10. UFI 登录为什么使设备屏幕出现锁定提示？原生应用也要登录吗？

UFI/原厂 WebUI 登录可能触发设备原有的屏幕锁定提示，外层认证和原厂页面不由这个面板实现。项目没有修改或绕过原厂锁屏机制。

原生应用通过本机 Unix socket 与 root 控制桥通信，不登录 WebUI，也没有 `INTERNET` 权限或直接申请 root。网页面板仍需要已有 UFI 认证 root 接口；加密请求不能代替该登录。

## 11. 构建需要什么？为什么未签名 APK 或更新后的 APK不能直接使用？

网页：Node.js 18+、npm。后端：Go 1.27+，完整互操作测试需要 `java`/`javac`。原生：PowerShell、JDK 17+、Android Platform 35、Build Tools 35 或兼容后续版本。无须 Gradle/Maven，也没有随源码附带的工具链。

`build.ps1` 默认输出未签名 APK 与构建清单；签名需显式提供 keystore、密码文件、alias 三项，身份存于仓库外。同包更新通常要求同一签名，而 root bridge 精确固定 APK 摘要；两层要求均需满足。见[构建](building.md)、[原生构建](../native-manager/README.md)。主机测试和几何检查不证明真实触摸、Android 生命周期或网络已完成验收。
