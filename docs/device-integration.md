# 设备集成边界

[English](device-integration.en.md) · [返回首页](../README.md)

这份源码提供可构建的管理层与网关参考实现，没有打包固件、root 获取工具或通用安装器。构建成功不等于已经具备可直接部署到任意 U30 Pro 的安装包。

## 已有运行环境

- 已取得 root 的原厂 Android 设备；需要可用的启动与恢复机制。
- 独立安装、来源与摘要可核对的 Android arm64 Mihomo。
- 固定运行根目录 `/data/adb/u30pro-vpn`，由 root 持有并限制其他用户访问。
- 匹配本机网络环境的网关基线与恢复信息，及 root 私有的 provider、状态和密钥。
- 网页面板需要已安装 UFI 及其认证 root 接口。源码不包含 UFI 的认证实现。

`web-manager/device/config.yaml` 是无订阅凭据的参考配置。它指向运行目录里的 provider；仓库没有附带该私有文件，也没有可直接使用的节点。`Auto` 和 `VPN` 均使用 select 组，没有定时测速配置。

## 原生应用信任

应用默认包名为 `com.codex.u30vpn`。root helper 的信任记录必须以安装后的实际身份生成，包括 schema、包名、UID、安装 APK 路径和 SHA-256；不能复用其他设备的 UID 或旧 APK 摘要。信任记录本身不随源码分发。

Android 构建默认输出未签名 APK，使用者应在仓库之外保管自己的签名身份。同包更新需要相同签名；helper 的精确 APK 校验还要求同步更新信任记录。项目没有公开原开发设备的签名材料或自动信任更新入口。

## 验证范围

仓库中的自动测试使用模拟控制器和虚构节点，不需要真实订阅，也不会连接设备进行节点测速。它们覆盖加密协议、输入校验、事务恢复、节点操作及界面几何等代码边界。

实际部署还需要核实转发、DNS、关闭时的原厂网络恢复、重启启动与故障恢复。不能把主机测试通过当作某个新固件已完成这些实机验证。首次集成应由了解设备恢复方式的维护者完成。
